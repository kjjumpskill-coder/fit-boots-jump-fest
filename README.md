# FIT-BOOTS UKRAINIAN JUMP FEST & ZUMBA 2026 — лендінг + адмін-панель

Готовий одностраничний сайт фестивалю (`index.html`) та демонстраційна адмін-панель (`admin.html`).

## Структура файлів

```
index.html          — головна сторінка (лендінг)
admin.html           — адмін-панель (прихована, не в навігації)
css/style.css         — дизайн-система та стилі лендінгу
css/admin.css         — стилі адмін-панелі
js/main.js            — анімації, форми, модалки, галерея
js/admin.js           — логіка адмін-панелі
assets/                — зображення (логотип, фото, галерея)
```

Відкрийте `index.html` у браузері — сайт повністю робочий локально.
Для публікації достатньо залити всю папку на будь-який хостинг (Netlify, Vercel, звичайний хостинг з підтримкою статики).

## Що вже працює "з коробки"

- Адаптивна верстка (mobile-first), анімації на скролі (GSAP + ScrollTrigger з CDN)
- Перехід "завіса" між частиною FIT BOOTS та GALA EVENT
- Валідація форм, модальні вікна реєстрації, заявок на розтермінування/команди
- Галерея з лightbox, картки інструкторів з детальним переглядом (drag-скрол)
- Вбудована Google-карта (без API-ключа, працює одразу) для обох локацій
- **Демо-адмінка** (`admin.html`, логін `admin` / пароль `festival2026`):
  реєстрації, чек-ін на фестиваль/gala окремо, статистика, заявки, звернення, CSV-експорт,
  легке редагування карток інструкторів
- Якщо GSAP не завантажиться з CDN (блокувальники реклами, відсутність інтернету) —
  сайт не ламається: весь контент залишається видимим, форми та модалки продовжують працювати.

## ⚠️ Що потрібно підключити перед реальним запуском

Сайт зараз працює в **демо-режимі**: реєстрації, заявки та звернення зберігаються
у `localStorage` браузера користувача (тобто тільки на його пристрої, дані не потрапляють
на сервер і не бачать інші відвідувачі). Це зроблено, щоб дизайн і UX можна було одразу
оцінити та протестувати без бекенду. Для продакшена потрібно:

### 1. Бекенд для реєстрацій
Замінити функції `saveArr()` / `loadArr()` у `js/main.js` та `js/admin.js` на реальні
запити до вашого сервера/бази даних (Google Sheets API, Airtable, Firebase, власний бекенд тощо).
Форма реєстрації (`#regForm` у `index.html`) вже містить усі потрібні поля.

### 2. Онлайн-оплата: MonoPay та LiqPay
У модальному вікні реєстрації є перемикач способу оплати (MonoPay / LiqPay) —
зараз він лише позначає вибір і "симулює" успішну оплату. Щоб зробити оплату реальною:
- **LiqPay**: підключити офіційний LiqPay Checkout widget (https://www.liqpay.ua/documentation/api/aquiring/checkout/doc) — потрібні `public_key`/`private_key` з кабінету.
- **MonoPay**: підключити Monobank Acquiring API (https://api.monobank.ua/docs/acquiring.html) — потрібен токен продавця.
- Після оплати сервер має підтвердити транзакцію (webhook) і лише тоді записувати
  статус "оплачено" в базу — зараз це робиться одразу на клієнті, що годиться лише для демо.

### 3. Надсилання заявок (форма контактів, заявки на команди/розтермінування)
Зараз форми зберігають дані локально. Потрібно підключити один із каналів:
- Telegram-бот (Telegram Bot API `sendMessage`)
- Email (наприклад, через сервіс типу SendGrid/Mailgun або власний SMTP-бекенд)
- CRM-таблиця (Google Sheets API, Airtable)

### 4. Авторизація адмін-панелі
`admin.html` зараз захищена лише на клієнті (логін/пароль перевіряються в браузері,
пароль видно у вихідному коді `js/admin.js`). **Це не є справжнім захистом** і
підходить лише для демонстрації. Перед реальним використанням:
- підключіть серверну авторизацію (Firebase Auth, Supabase Auth, або власний бекенд із сесіями),
- перенесіть усі дані реєстрацій у захищену базу даних на сервері,
- обмежте доступ до `admin.html` за IP або через окремий піддомен, якщо це можливо.

### 5. Google Maps
Наразі використовується безкоштовний iframe-embed Google Maps (без API-ключа) —
він одразу працює, але має обмежений функціонал. Якщо потрібні кастомні мітки,
кластеризація або розширена стилізація карти — підключіть Google Maps JavaScript API
з власним ключем (https://developers.google.com/maps/documentation/javascript/overview).

### 6. Фото інструкторів
Наразі на сайті — 6 карток-заглушок із силуетом. Коли зʼявляться реальні фото,
заміните масив `instructors` у `js/main.js` (рядки біля `var instructors = [...]`) —
додайте `photo: 'assets/instructor-1.jpg'` для кожного і завантажте самі фото в `assets/`.
Демо-CMS в адмінці (вкладка «Інструктори / Галерея») дозволяє редагувати імена та
посилання на фото, але для реальної публікації ці зміни потрібно підʼєднати до
того самого бекенду, що і реєстрації.

## Технічний стек

- Чистий HTML/CSS/JavaScript (без збірки, без залежностей npm)
- GSAP 3 + ScrollTrigger + ScrollToPlugin (з CDN cdnjs.cloudflare.com)
- Google Fonts: Bebas Neue, Quicksand, Playfair Display, Caveat
  (Bebas Neue та Quicksand — прямо з брендбуку; Playfair Display — для розділу GALA;
  Caveat — рукописний акцент замість фірмових платних шрифтів Heaters/Lambola з брендбуку,
  яких немає у Google Fonts)

## Продуктивність

Усі фото сконвертовані у WebP та стиснуті (у т.ч. HEIC-файли з телефону) —
загальна вага зображень зменшена приблизно у 20 разів порівняно з оригіналами.
Галерея використовує `loading="lazy"`.
